# Правила прокси

bindhosts умеет запускать локальный TLS-прокси, который перехватывает запросы к
указанным доменам и перезаписывает или блокирует их по пути URL. Он работает
независимо от правил hosts: hosts решает, что блокируется через `0.0.0.0`,
прокси решает, что отвечается локально.

## Включение

1. Перейдите в представление **Proxy** на странице правил.
2. Включите переключатель рядом с вкладкой.
3. Добавьте хотя бы один домен и одно правило.
4. Нажмите кнопку action.

При первом включении локальный CA создаётся в `/data/adb/bindhosts/proxy/certs/`
и устанавливается в системное хранилище доверия. Закрытый ключ не покидает
устройство и не входит в модуль.

## Объявление домена

Прокси подписывает сертификаты только для доменов, о которых ему сообщили.
Добавьте строку hosts в `proxy/custom.txt`:

```
127.0.0.1 api.example.com
```

Этот адрес записывается в системный hosts, поэтому запросы к домену попадают
в локальный прокси, а не в интернет. Одна строка на домен; CA может подписать
любое их количество.

## Правила

Одно правило на строку. `<path>` сравнивается с путём запроса; завершающая `*`
делает совпадение префиксным.

```
mock    <path> [body]     ответить локально телом body
patch   <path> <json>     заменить значения ключей и переслать
forward <path>            передать запрос реальному серверу
block   <path>            закрыть соединение
```

Пример:

```
mock    /api/version {"code":0,"data":{"haveUpdate":false}}
patch   /api/* {"appVersion":"9.9.9"}
forward /api/*
block   /ads/*
```

`patch` заменяет только значение одноимённых ключей, остальные байты тела
остаются нетронутыми — порядок полей, формат чисел и пробелы сохраняются.
Правило `patch` само пересылает запрос, не добавляйте отдельное `forward` для
того же пути.

Правила проверяются по порядку в файле, побеждает первое совпадение. Пути без
правила передаются дальше.

## Наборы правил

`proxy/sources.txt` принимает по одному URL на строку. Загрузки кэшируются в
`proxy/cache/` и используются, когда все загрузки не удались, поэтому запуск
без сети всё равно даёт последний известный набор.

## Загруженные наборы правил доступны только для чтения

Правила из `sources.txt` попадают в продукт, но их нельзя редактировать в WebUI.
Страница запроса помечает их тегом `SRC` и не предлагает кнопку удаления. Чтобы
отключить загруженное правило, уберите его URL из `sources.txt`.

В представлении Hosts у строк `SRC` тоже нет кнопки: загруженное правило нельзя
удалить со страницы запроса. Уберите его URL из `sources.txt`.

## Белый и чёрный списки

Оба являются представлениями `proxy/custom.txt`:

- **Белый список** показывает правила `forward`
- **Чёрный список** показывает правила `block`

Редактирование любого из них меняет `proxy/custom.txt`. Это не отдельные файлы.

## Отключение

Выключение прокси останавливает демон, освобождает `127.0.0.1:443` и удаляет
записи прокси из файла hosts. Файлы правил и CA сохраняются, поэтому повторное
включение не требует настройки.

CA остаётся в хранилище доверия до следующей перезагрузки. На ходу её не
размонтировать: точка монтирования находится в общей группе распространения.

## Диагностика

Смотрите `/data/adb/bindhosts/proxy.log`:

| Строка | Значение |
|---|---|
| `loaded N system roots` | Должно быть не равно нулю, иначе запросы к серверу не пройдут |
| `signed leaf for <домен>` | Для домена выпущен сертификат |
| `drop <домен> (not in proxy rules)` | Заблокированный домен дошёл до прокси |
| `daemon exited ... (fail=x/10)` | Демон постоянно падает; после 10 коротких запусков прокси отключается сам |

Если прокси включён, но запросы не перехватываются, проверьте, что у домена есть
строка `127.0.0.1` в `proxy/custom.txt`.
