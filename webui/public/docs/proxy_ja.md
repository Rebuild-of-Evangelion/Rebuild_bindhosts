# Proxy ルール

bindhosts はローカル TLS リバースプロキシを実行でき、指定したドメインへのリクエストを
URL パス単位で書き換えたり遮断したりします。hosts ルールとは独立して動作します。
hosts は `0.0.0.0` で何を塞ぐかを決め、proxy は何をローカルで返すかを決めます。

## 有効化

1. ルールページで **Proxy** ビューに切り替えます。
2. タブ横のスイッチをオンにします。
3. ドメインを 1 つ以上、ルールを 1 つ以上追加します。
4. action ボタンを押します。

初回有効化時に `/data/adb/bindhosts/proxy/certs/` にローカル CA が生成され、
システムの信頼ストアにインストールされます。秘密鍵は端末外に出ず、モジュールにも含まれません。

## ドメインの宣言

プロキシは「知らされた」ドメインにしか証明書を発行しません。
`proxy/custom.txt` に hosts 行を追加します：

```
127.0.0.1 api.example.com
```

この行がシステム hosts に書き込まれ、そのドメインへのリクエストが
インターネットではなくローカルプロキシに届きます。1 ドメイン 1 行で、CA はいくつでも署名できます。

## ルール

1 行 1 ルール。`<path>` はリクエストパスと照合され、末尾の `*` は前方一致になります。

```
mock    <path> [body]     body をローカルで返す
forward <path>            実サーバーへそのまま転送
block   <path>            接続を閉じる
```

例：

```
mock    /api/version {"code":0,"data":{"haveUpdate":false}}
forward /api/*
block   /ads/*
```

ファイル順に照合し、最初に一致したものが適用されます。一致するルールがないパスは転送されます。

## ルールセット

`proxy/sources.txt` に 1 行 1 URL を書きます。ダウンロード内容は `proxy/cache/` にキャッシュされ、
すべてのダウンロードが失敗したときに再利用されるため、オフラインでも前回のルールセットが得られます。

## ダウンロードしたルールセットは読み取り専用

`sources.txt` から取得したルールは製品にマージされますが、WebUI では編集できません。
クエリページでは `SRC` タグが付き、削除ボタンは表示されません。
ダウンロードしたルールを使わないようにするには、`sources.txt` からその URL を外してください。

Hosts ビューの `SRC` 行にはボタンがありますが、これも削除ではありません。
ドメインを `hosts/whitelist.txt` に書き込み、次回の再構築でスキップさせます。

## ホワイトリストとブラックリスト

どちらも `proxy/custom.txt` のビューです：

- **ホワイトリスト** は `forward` ルールを一覧表示
- **ブラックリスト** は `block` ルールを一覧表示

どちらを編集しても `proxy/custom.txt` を書き換えます。別ファイルではありません。

## 無効化

proxy をオフにするとデーモンが停止し、`127.0.0.1:443` が解放され、
hosts から proxy エントリが削除されます。ルールファイルと CA は保持されるため、
再度有効化しても設定は不要です。

CA は次回の再起動まで信頼ストアに残ります。マウントが共有伝播グループにあるため、
実行中にはアンマウントできません。

## トラブルシューティング

`/data/adb/bindhosts/proxy.log` を確認してください：

| ログ | 意味 |
|---|---|
| `loaded N system roots` | 0 以外である必要があります。0 だと上流リクエストが失敗します |
| `signed leaf for <ドメイン>` | そのドメインの証明書が発行されました |
| `drop <ドメイン> (not in proxy rules)` | 遮断対象のドメインがプロキシに到達しました |
| `daemon exited ... (fail=x/10)` | デーモンが繰り返し終了しています。短命な起動が 10 回続くと proxy は自動で無効になります |

proxy が有効なのにリクエストが傍受されない場合は、
そのドメインの `127.0.0.1` 行が `proxy/custom.txt` にあるか確認してください。
